# Working in this repository

Notes for anyone — human or agent — making changes here. Conventions live in
`.github/copilot-instructions.md`; the Copilot agent suite is described in
`.github/copilot-agents.md`. What the app *is* belongs in `README.md`.

## What this is

A second screen for two live fantasy drafts, run on one laptop, once a year. It estimates
whether a given player survives until your next turn, by simulating each intervening
league-mate from five or six years of their own draft history.

That shape drives most of the decisions below. There is no database, no scheduler, no
external service in the request path, and no runtime dependency. Everything the board needs
is downloaded ahead of time by `npm run draft:prep` and read from `data/`.

## Commands

```bash
npm test              # 129 tests, no network
npm run build         # tsc
npm start             # build, then serve on :3005
npm run start:fast    # serve without rebuilding
npm run draft:prep    # download ADP + Sleeper metadata, rebuild manager profiles
npm run replay -- A-LEAGUE 2025 500    # score the model against a held-out draft
```

`npm run draft:prep` hits the network; nothing else does, tests included.

## Layout

```text
src/config/league.ts       confirmed CBS league settings, single source
src/services/              the model: pool, profiles, board, survival simulation
src/api/routes/board.ts    draft-day endpoints and session state
src/api/server.ts          routing and static file serving
public/index.html          the entire UI, one file, no build step
scripts/                   data fetch, profile build, replay harness
historical-draft-data/     source data — CBS exports, hand-placed
data/                      generated by draft:prep, not source
claude/                    optional Claude tools — separate package, separate deps
```

`claude/` is deliberately outside everything above. It has its own `package.json`, it is
excluded from `tsconfig.json`, and nothing in `src/` imports it. Adding a dependency there
must never become a dependency here: the root install, build, tests and `npm start` have to
keep working with `claude/node_modules` absent entirely. If you find yourself importing from
`claude/` into `src/`, that is the mistake — the sidecar is allowed to fail, the board is not.

The MCP sidecar is read-only by design. Do not add tools that record picks, undo them, or
resync the board; picks stay in the UI where a human confirms them, for the same reason a
single click on the grid never drafts anybody.

## Things that will bite you

**Silent wrongness is the failure mode that matters.** A board that shows plausible numbers
about the wrong manager is worse than one that crashes. That is why setup audits the pasted
draft order and the slot, and why unmatched names are recorded as placeholders rather than
skipped — a skipped pick puts every later pick on the wrong team.

**The draft is live and unrepeatable.** A change to the draft-day path needs a test that
would fail if it broke, and ideally a run through a real board. There is no rollback at 7pm
on draft night.

**Calibration is measured, not assumed.** `CALIBRATION_ANCHORS` in `survival-engine.ts` maps
raw simulation output onto observed survival. If you change how the simulation picks, re-run
`npm run replay` across the held-out drafts and check the buckets still track before
believing the output.

**Scoring format is load-bearing.** Both leagues are half-PPR. Reach is measured against
market ADP, so pulling the wrong format silently mismeasures every manager's tendencies.
`src/config/league.ts` holds it.

**The ADP feed is shallower than the pool needs.** Half-PPR ranks fewer players than full
PPR, so the pool is supplemented from the PPR feed for names half-PPR does not rank —
purely so they resolve in the pick box. Do not use a fallback player's ADP as if it were on
the same scale; `adpFromFallback` marks them.

## Style

Plain records over classes. Exported functions carry JSDoc with `@param` and `@returns`.
Comments explain why, not what. Validate at entry points with `validators.ts` and throw
`TypeError` — the API layer turns that into a 400 with the message attached.

The UI builds HTML strings, so everything interpolated from data goes through `escapeHtml`.
